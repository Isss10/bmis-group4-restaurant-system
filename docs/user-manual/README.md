# 餐厅预订与点餐系统 — 用户手册

JC2001 BMIS Group 4 · 安装与操作指南（维护人：JIAYI TAN）

## 1. 系统简介
面向中小型餐厅的在线预订 + 点餐原型：并发安全订座、菜单浏览与下单、会员积分、评价、经理数据看板。

## 2. 环境要求
- Python 3.11
- MySQL 8.0（InnoDB）
- Node.js 18+（前端 Vue 3）

## 3. 后端安装与启动
```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt -r requirements-dev.txt
Copy-Item .env.example .env   # 填入 APP_JWT_SECRET_KEY 与数据库连接
python -m alembic upgrade head
uvicorn src.presentation.api.main:app --reload
```

## 4. 用户角色、登录与首次访问

系统的五个主要模块包括：预约、点餐及员工后台、会员与忠诚度、菜品评价、管理分析。以下操作流程需结合真实系统界面核对。

| 角色 | 主要功能 | 注意 |
| --- | --- | --- |
| 顾客 Customer | 登录、预约、浏览菜单、下单、查看积分/优惠券、评价已点菜品 | 只能操作自己的业务数据 |
| 服务员 Waiter | 查看预约/订单、处理服务相关状态 | 以角色权限配置为准 |
| 经理 Manager | 查看统计看板、餐桌周转率、需求热力图等 | 仅对获授权账户开放 |
| 管理员 Admin | 维护角色和系统管理相关功能 | 最小权限原则 |

系统以 Python 3.11、FastAPI、MySQL、Vue 3 为主要技术栈；后端 API 文档按部署环境提供的 `/docs` 页面查看。

### 4.1 登录与账户安全

1. 打开系统登录/注册入口。
2. 选择已有账号登录，或使用注册功能创建顾客账号（如果当前版本开放注册）。
3. 输入有效凭据后，检查页面是否展示与你的角色相符的功能。
4. 退出时使用“登出/退出登录”操作；不要在共享电脑保存密码。

遇到 `401`，确认是否已登录及令牌是否过期；遇到 `403`，联系管理员确认账号角色，不要借用他人令牌。

### 4.2 前端首次访问

顾客端、员工端和经理端的实际访问网址由部署负责人提供。不要在未核对项目配置前写死端口或假定功能菜单已上线。建议每个角色提供一张真实登录成功截图，并记录测试账号的**角色**，不要记录密码或 JWT。

## 5. 模块一：餐桌预约（Reservation）

**使用对象：** 顾客；员工可依据权限查看或更新预约状态。

1. 登录顾客账户，进入“预约/Reservation”入口。
2. 根据界面提供的选项选择用餐日期、时间和餐桌。
3. 在提交前确认桌位、日期、时间及顾客信息。
4. 提交预约。成功后在预约记录中核对预约编号和状态。
5. 如允许取消或修改，使用本人预约记录中的相应操作；可用状态转换以系统实际规则为准。
6. 若遇到桌位冲突，应提示重新选时间/餐桌，**不能显示为预约成功**。

**并发安全验收：** 针对同一桌位和时段并发发出 50 次预约请求，仅允许 1 次成功，49 次应报告正确的预约冲突（预期 HTTP 409，业务错误码 20001），数据库最终只有 1 条有效预约。该结论必须由真实 MySQL 测试记录支持，不能只凭代码存在或测试被收集。

**业务状态：** 设计包括临时占座、自动过期、预约状态机；实际界面操作及状态名称须由预约模块负责人核对后补充截图。

## 6. 模块二：菜单、点餐与员工后台（Ordering & Staff）

### 4.1 顾客浏览菜单和点餐

1. 登录顾客端，打开“菜单/Menu”。
2. 使用菜品分类浏览菜品名称、说明及展示价格。
3. 选择需要的菜品和数量，检查下单清单。
4. 提交订单后查看是否生成订单记录及其状态。
5. 若菜品不可售、数量无效或提交失败，根据页面提示调整或联系店员。

### 4.2 员工处理预约和订单

1. 使用有权限的员工账户登录后台。
2. 进入预约列表，按日期、状态或桌位等界面已提供的条件筛选。
3. 打开预约详情并根据权限更新预约状态，核对更新后的结果。
4. 进入订单列表，查看菜品、数量、订单状态与关联预约。
5. 处理订单后再次检查列表；对异常情况按内部流程联系经理。

> 不能假定所有筛选项和按钮都已实现。由 Ordering/Staff 负责人把真实菜单和后台截图插入本节。

## 7. 模块三：会员与忠诚度（Membership & Loyalty）

**使用对象：** 顾客及获授权管理员。

1. 顾客登录后打开会员中心（入口名称以实际 UI 为准）。
2. 查看账户资料、会员等级以及当前积分余额。
3. 查看积分变动记录，核对来源、扣减与到期信息。
4. 若系统支持优惠券领取/使用，进入优惠券页面查看有效期和适用条件。
5. 下单前查看优惠券叠加规则；系统应对不符合规则的组合给出提示。
6. 管理员通过授权页面执行角色相关操作，普通顾客不可访问管理功能。

**注意：** 积分过期规则、等级门槛、优惠券叠加优先顺序需要与最终冻结的业务规则一致；本手册不自行假定具体金额或比例。

## 8. 模块四：菜品评分与评论（Ratings & Reviews）

1. 顾客登录后进入自己已完成的菜品订单或评价入口。
2. 选择真实购买过的菜品，填写评分和评论内容。
3. 提交后确认系统返回的受理/审核状态。
4. 如采用“先审核后展示”，评论在管理员审核通过前不应在公开列表中出现。
5. 顾客尝试评价未购买菜品、重复评价或超过频率限制时，应收到明确拒绝提示。
6. 获授权员工在评论审核队列查看待审核项，选择通过或拒绝并记录审核结果。
7. 在菜品展示页查看统计评分。设计采用贝叶斯平均排名，而非简单平均。

> 具体评分范围、按钮名称、评论修改规则和限制次数，以评论模块实现及业务契约为准。

## 9. 模块五：经理分析与推荐（Analytics & Recommendation）

**使用对象：** Manager/Admin 等获授权角色。

1. 登录经理后台，进入分析看板入口。
2. 选择系统支持的日期范围或统计条件。
3. 查看营业收入趋势，确认统计区间和金额单位。
4. 查看桌位周转率、小时需求热力图和 no-show 率，阅读图表图例及指标定义。
5. 如系统开放推荐展示，查看推荐结果与其适用对象。
6. 需要分享结果时，只使用实际支持的导出方式；如果没有导出按钮，可记录可见图表并注明日期范围。

**解释规则：** no-show 的判定窗口、推荐算法参数及 Precision@K/MAE 评估指标应与最终测试报告一致；不得凭空填入“已达到”的数值。

## 10. 常见问题和排查

| 症状 | 首先检查 | 处理方式 |
| --- | --- | --- |
| 无法打开网站 | 服务器/容器是否启动、URL 与端口是否正确 | 联系部署负责人确认访问地址 |
| 登录失败或 `401` | 账号凭据、会话/令牌是否过期 | 重新登录，不分享令牌 |
| 操作遭拒并返回 `403` | 当前角色是否具有权限 | 联系管理员核实权限 |
| 预约时显示冲突 `409` | 同一桌位与时段是否已被占用 | 改选可用时段；不得强制覆盖 |
| 提交返回 `422` | 输入数据是否符合接口校验 | 按字段提示修改日期、数量等 |
| 后台列表为空 | 是否切换了日期/状态过滤条件 | 清除过滤条件并检查账号权限 |
| 本地测试无法连接 MySQL | 连接主机、端口、服务及测试数据库配置 | 先检查环境，不修改生产数据库 |
| 测试显示 `skipped` | 数据库配置和测试 marker | `skipped` 不算并发测试通过 |
