这是未来实现的验收计划，不是已执行的测试报告。M7 负责预订并发、集成测试；M1 负责预订业务接口。
业务须以 M1 最终契约为准，下面 300xx 引用契约对齐评审。

## 1. 测试环境与方法
- Python 3.11、pytest/pytest-asyncio、项目声明的 HTTP 测试客户端和 pytest-cov。
- 单元测试使用 repository fake；接口测试使用 FastAPI TestClient/依赖替换。
- 唯一约束、事务、行锁、刷新及角色管理并发测试必须使用专用 MySQL 8 InnoDB。
- 所有账号、邮箱、订单均为合成数据；JWT key 每轮随机生成，不上传真实凭证。
- 时间敏感测试注入固定 UTC clock，覆盖到期前、恰好到期、到期后。
- 下面每个用例均断言 HTTP、response DTO、DB 状态；失败不得造成部分持久化。

## 2. 需求到验收场景
| ID | 需求 | 场景/输入 | 预期 | 级别 |
|----|------|----------|------|------|
| RESV-01 | FR-RES-01 | 合法顾客提交预订：空闲桌、合法时段、人数符合桌型上限 | 预订成功，状态 held，数据库新增一条预订记录，返回预订号 | 单元+集成 |
| RESV-02 | FR-RES-01 | 顾客预订已被占用的桌+时段 | 返回冲突，DB 不新增预订 | 接口 |
| RESV-03 | FR-RES-01 | N个客户端同时提交【同一桌子、同一时段、合法人数】并发抢座 | 恰好1条预订成功，其余全部返回冲突，数据库仅1条记录 | MySQL并发 |
| RESV-04 | FR-RES-02 | held状态预订超过保留时长（600s）自动过期 | 状态变更为 cancelled，桌子释放，可被新预订占用 | 单元+接口 |
| RESV-05 | FR-RES-02 | 顾客主动取消处于held/confirmed状态的预订 | 状态改为cancelled，桌位释放；已入座订单不可取消 | 接口 |
| RESV-06 | FR-RES-03 | waiter/manager 查询全部预订；customer 只能查看自己的预订 | 权限隔离，越权访问返回403 | 集成 |
| RESV-07 | FR-RES-03 | 不存在的预订ID查询、非法桌ID、日期格式错误 | 参数校验失败，返回400，DB无变更 | 参数化接口 |
| RESV-08 | FR-RES-04 | 预订确认后，下单点餐，跨模块读取预订ID | 订单绑定预订记录，数据在后端、后台页面一致 | 端到端集成 |

所有允许/拒绝检查直接发 HTTP，不能仅靠 Vue 路由测试。role enum 不自动继承。
每个模块必须显式列出 staff/manager/admin 集合；匿名刷新使用 refresh 凭证单独验证。
测试矩阵覆盖错误路径，不能只证明“合法顾客预订成功”。

## 3. 与 Member1 的交接验收（M1实施接口）
| ID | 场景｜预期 |
|----|------|------|
